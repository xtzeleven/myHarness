# ADR 0010 — 项目定位调整：可度量的 Harness，随模型代际实测

**Status**: Accepted
**Date**: 2026-11-21
**Stage**: M9
**Relates to**: [ADR-0001](0001-three-layer-harness.md), [ADR-0008](0008-process-capability-expansion.md), [improvement-plan.md](../improvement-plan.md) §2、§7 D4 / D6 / D7

## 背景

项目立意是"验证三层 Harness 有效"，但到 2026-11：

- 大部分资产是写给模型读的文字（软约束），已有的硬约束在本机失效（ADR-0009），且没有任何度量能证明"有效"。
- 模型持续变强。Harness 里"补偿模型不行"的部分会贬值，"定义什么算对、谁说了算"的部分会升值（方案 §2.1 五种成分：①能力补偿 ②编排补偿 ③信息补偿 ④验证 ⑤权责）。
- 现有投入集中在贬值最快的 ①②，最有战略价值的对照实验还不存在。

## 决定

### D6-A：采纳新定位，主视角保留时间轴三层

- 项目定位从"三层 Harness 方法论"调整为 **"可度量的 Harness：哪些该留、哪些该拆，随模型代际实测"**。
- 对外主视角仍是时间轴三层（约束 / 反馈 / 门禁）；五种成分作为**规则标签**，不替换主视角。P1 出代际数据后再评估是否改为"意图 / 验证 / 权责"（方案 §2.3，即 D6-B）。
- 按成分投资：冻结 ①②；③ 从"每会话注入"改为按需查询；④⑤ 机制化并加强。
- 拆规则只按数据，不按预测（方案 §2.5）。

### D4：ADR-0008 Tier 2–4 冻结

冻结到 M9-P1 首份报告出来后再评估。理由：会进一步拉大"框架 ≫ 载体"，且 Tier 2 的触发条件（M8-T3 完成）本身也未满足。ADR-0008 的 Tier 1 资产保留不动。

### D7：代际复跑频率 = 每次主要模型发布

- 每次主要模型发布，用**同一版本**的 `bench/` 任务集重跑 C0 / C2，结果追加到 `bench/generations.md`。
- 任务集打版本号后冻结；改任务集 = 新版本，旧数据不混。
- 不做固定季度复跑：模型不变时复跑只测到随机性。

### D3：首批对照实验手工跑

首批 3 任务 × C0/C2 × 每组合 2 次，本机手工跑 Claude Code，用 markdown 记录，不写自动化脚本（避免实验本身变成又一个框架）。第二批再考虑自动化。

## 替代方案

| 候选                                       | 否决原因                                                |
| ------------------------------------------ | ------------------------------------------------------- |
| D6-B 新定位 + 主视角改为意图 / 验证 / 权责 | 方向对，但现在没数据支撑；先打标签、攒数据，P1 后再评估 |
| D6-C 维持原定位                            | 继续扩 ①② 类资产，与模型进步方向相反；"有效"仍无法证明  |
| D4 照原计划推进 Tier 2–4                   | 载体停滞时扩框架，重复 7 月"框架修框架"的问题           |
| D7 固定每季度复跑                          | 模型未变时复跑无信息量，徒增维护成本                    |

## 后果

- README 项目简介、CLAUDE.md §5 项目性质同步新定位。
- 每条规则后续要带成分标签；① 类规则要写退役条件（M9-P2）。
- `bench/` 成为核心资产：README 的 "Real-world coding benchmark" 由它兑现。
- 风险：P1 样本小、随机性大 → 首批只看"有没有、哪层拦"，不看百分比。
